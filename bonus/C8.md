# C8. Semantic Cache - Phân tích phía trên KV Cache

**Thiết lập:** 
Chạy script mô phỏng offline: `.venv/bin/python bonus/serving-regimes/semantic-cache-demo.py --offline`

**Số liệu:**
- Hit rate đạt 3/8 = 38%
- LLM calls saved: 3 (~750ms decode skipped)

**Chẩn đoán False Hit & False Miss:**
Do lab sử dụng phương pháp dự phòng (fallback) là keyword overlap / bag-of-words (vì không bật server embedding chuyên dụng), nên sinh ra các lỗi ngớ ngẩn:
- **False Miss (Trượt oan):** Câu 2 "Explain TTFT and TPOT." và Câu 4 "What does time to first token mean?". Cùng hỏi về TTFT nhưng không có từ nào trùng nhau -> Similarity = 0.0 -> Miss.
- **False Hit (Trúng nhầm):** Nếu hỏi "What is NOT goodput?", nó vẫn trùng từ khóa "goodput" với câu 1 -> Similarity cao -> Hit và trả về đáp án sai bét.

**Phân tích (Vượt ra ngoài deck):**
Không có bất kỳ một Threshold (ngưỡng) nào có thể sửa được cả 2 lỗi trên. Nếu hạ Threshold để bắt được False Miss, hệ thống sẽ dính hàng loạt False Hit. Nếu tăng Threshold để chống False Hit, hệ thống lại bỏ sót False Miss.
Lý do là vì các mô hình sinh text (decoder-only) được huấn luyện để dự đoán token kế tiếp, nó không có khả năng chắt lọc toàn bộ ngữ nghĩa câu thành 1 vector như các Embedding models chuyên dụng (Qwen3-Embedding, BGE-M3). 

**Rủi ro bảo mật:**
Dùng chung Semantic Cache hoặc KV Cache giữa nhiều người dùng (multi-tenant) có nguy cơ rò rỉ dữ liệu qua timing attack (nếu thấy câu hỏi trả về ngay lập tức, attacker biết tenant khác vừa hỏi câu tương tự). Ở production, cache phải được "salt" theo từng user/tenant riêng biệt.
