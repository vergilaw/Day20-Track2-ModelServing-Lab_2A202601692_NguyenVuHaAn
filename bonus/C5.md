# C5. Challenge "Mô hình nhỏ nhất vẫn hữu ích" (Unsloth Dynamic)

**Thiết lập:**
Thay vì chạy bản `UD-Q4_K_XL` (4-bit), tôi khảo sát thêm bản lượng tử hóa siêu nhỏ `UD-IQ2_M` (hệ số 2-bit, kích thước cực kỳ bé) để xem giới hạn chịu đựng của mô hình ở mức nào thì nó "mất não".

**Số liệu & Kết quả 5 Prompts trên UD-IQ2_M:**
1. *Dịch "Hello" sang tiếng Pháp* -> "Bonjour" (Pass - đúng)
2. *Thủ đô của Việt Nam là gì?* -> "Hanoi" (Pass - đúng)
3. *Tính 15 + 27 = ?* -> "42" (Pass - đúng)
4. *Viết một đoạn code Python in ra số chẵn từ 1 đến 10* -> Code sinh ra lộn xộn, syntax error, thụt lề sai (Fail - mất khả năng suy luận logic code).
5. *Giải thích PagedAttention* -> Sinh ra toàn text lặp lại (hallucination loop: "PagedAttention is is is is...") (Fail - vỡ ngôn ngữ).

**Phân tích (Vượt ra ngoài deck):**
- **Điểm gãy (Breaking point):** Mô hình lượng tử hóa 2-bit (IQ2_M) bảo toàn khá tốt **kiến thức sự thật (factual knowledge)** cho các câu hỏi đơn giản, nhưng **suy luận logic (reasoning) và ngôn ngữ chuyên ngành** bị phá hủy hoàn toàn.
- **Quyết định triển khai:** Nếu RAM máy cực kỳ hạn hẹp, ta KHÔNG NÊN dùng bản 2-bit cho các tác vụ RAG hay code generation (sẽ ra rác). Chỉ nên dùng 2-bit cho các task trích xuất thực thể đơn giản. Còn để chạy agent hay hỏi đáp phức tạp, `UD-Q4_K_XL` (4-bit) là giới hạn cuối cùng (sweet spot) mà ta nên triển khai để cân bằng giữa RAM và chất lượng. Việc nén quá mức không tiết kiệm được thời gian nếu câu trả lời vô giá trị.
